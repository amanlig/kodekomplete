# First Android app — manual Google Play internal testing

The first artifact is a standalone release build of aiNavLog's current UI.
Electrical uses visibly labeled demo readings; Engine and Routes are coming-next
screens. It launches without Metro, a laptop or a live device endpoint. Rust,
Bluetooth scanning and phone-local instrument storage are not yet packaged.

## Build and download

From `aiNavLog/user-interface/`, with Node 24:

```sh
npm ci
npx eas-cli@latest login
npm run android:configure
npm run android:archive
npm run android:build
```

Configuration links the existing organization project; archive inspection saves
`builds/archive`. Do not rerun the inspection onto an existing nonempty directory
unless intentionally replacing that generated archive. The wrapper supports EAS
flags after `--`: `npm run android:archive -- --force` replaces only that archive.

The wrapper sets `EAS_PROJECT_ROOT` to the UI directory and `EAS_NO_VCS=1` so a
cloud build does not archive the parent repository or the private investment
project. `.easignore` additionally excludes local environment files, credentials,
node_modules, generated native directories and previous artifacts. EAS regenerates
Android from app configuration. This mode does not create a Git commit; record
source changes with the artifact when managing releases.

The build profile forces `EXPO_PUBLIC_DEMO_MODE=1` and disables dotenv loading.
A desktop endpoint cannot override the standalone demo. The Play profile is
`distribution: store` even though its deployment track is internal testing;
EAS `distribution: internal` means a directly installable APK, not a Play track.
The optional `npm run android:apk` profile is for direct installation and is not
needed for the selected first Play deployment.

When EAS reports success, open the build page and download its **Android App
Bundle (.aab)**. AAB files are uploaded to Play; they are not directly installable
by tapping the file on a phone. The completed artifact and checksum are recorded
in [the corrected release evidence](android-corrected-build-2026-10-13.md).

`autoIncrement` is intentionally disabled for this manual first workflow. Before
uploading a later build, increase `expo.android.versionCode` in app.json beyond
any code already used in Play, then rebuild. Changing only version text is not
enough. No scheduled builds or automatic uploads run.

## Manually create the internal release

1. Sign into [Google Play Console](https://play.google.com/console/) using the
   verified organization account. Create an app named **aiNavLog**, select its
   default language and **App** category, and choose its intended free/paid model.
   Complete the declarations presented by Console.
2. Open **Test and release → Testing → Internal testing**. Complete the required
   setup tasks shown for this track. Set up Play App Signing when prompted; Google's
   generated app signing key is the documented first-upload option. The signed
   EAS bundle supplies the separate upload signature.
3. Under **Testers**, create/select an email list, including your own Google account
   for the first installation. Save the tester configuration.
4. Under **Releases**, create a new release. Upload the completed **.aab**. Verify
   the package, version name and version code match the build evidence.
5. Name the release **1.0.0 — first internal demo** and paste the notes below. Review
   the errors/tasks shown by Console, complete the required ones, and start rollout
   to **internal testing**. This does not select the Production track.
6. Copy the internal-test opt-in link. On an Android phone signed into an eligible
   tester account, open the link, opt into the test and install through Google Play.
   The first test link may take several hours to become available.

Console labels can change; use the named internal testing track and inspect the
release's target before rollout. The owner completes all Play declarations,
agreements, tester membership and rollout; the assistant has not accessed Console.

## First installed-app check

- Launch from Google Play with the laptop/Metro server stopped.
- Open Electrical; confirm the sample-reading label and changing House values.
- Check Starter shows volts, with current and charge as dashes.
- Open Engine/Routes; confirm coming-next screens and return to Home.
- Background and resume; verify readings recover and navigation still works.
- Close and reopen the app. Record phone model, Android version, app version/code
  and any errors. No instrument-persistence claim applies to this UI-only build.

Installation and update qualification are not proven by JavaScript export or a
successful cloud build. The next native integration build needs Rust target
packaging, Expo native adapters, Bluetooth permissions/scanning, protected key
storage and SQLite persistence. It will use the established package/signing path.
